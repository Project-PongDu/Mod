	   화력 지원 / 드론 실체 차량 (fire_support drone)

	   PerCom(KBPR3Team, MIT)의 droneMm.fbx를 분해해서 만들었다. 원본은
	   본체·로터·랜딩기어가 전부 융합된 단일 메시(50,081 tris)라 그대로는
	   파트 분리가 불가능했고, 다음 처리를 거쳤다:

	   - 연결 요소 분해로 로터 4개(90/80/75/70 verts)를 본체에서 분리
	   - 각 로터의 회전축을 180도 점대칭 최적점으로 산출
	       prop A ( 3.8952,  1.4192)  r=4.146  theta= 20.0
	       prop B (-1.3534,  3.8956)  r=4.124  theta=109.2
	       prop C (-3.8318, -1.4123)  r=4.084  theta=200.2
	       prop D ( 1.4169, -3.8719)  r=4.123  theta=290.1
	     대칭 잔차 0.14~0.47% (블레이드 span 대비) -> 축 정확
	   - 22.5도 간격 8프레임을 구움. 2엽이라 주기가 180도이므로 8프레임이
	     한 바퀴다. 프레임마다 로터 4개가 전부 들어 있어 파트는 하나뿐이며,
	     헬기의 heliblade/helibladeSmall 2파트 구조가 필요 없다.
	   - 본체는 3,000 tris로 감축. Hausdorff RMS가 원본 대비 0.013%,
	     bbox는 소수점까지 동일 -> 원본 49,263 tris가 형상 대비 과잉이었다.

	   블레이드 좌표는 원본 지오메트리 공간 절대 위치를 그대로 유지했으므로
	   part model offset이 전부 0이다 (헬기는 0 9 1.5 같은 실측값 필요).

	   ─── 스케일 산출 ───
	   VehicleScript.Loaded()가 extents / physicsChassisShape /
	   shadowExtents / shadowOffset / centerOfMassOffset 전부에
	   getModelScale()(= 아래 vehicle 블록의 model{scale})을 곱한다.
	   따라서 스케일을 vehicle 블록에 몰아두고 model 스크립트는 1.0으로
	   두면 이 값들을 메시 단위 그대로 적을 수 있다.

	     프로펠러 포함 최대 span = 8.28 메시 유닛 (blade3 프레임 기준)
	     목표 월드 span         = 약 2.2 유닛 (바닐라 승용차 전장 5.2 대비)
	     model scale            = 2.2 / 8.28 = 0.265

	   ※ 이 스케일과 shadowExtents는 인게임 1회 확인이 필요한 시작값이다.
	     너무 크면 model{scale}만 줄이면 extents/그림자가 같이 따라간다.

	   ─── 헬기에서 그대로 가져온 설계 ───
	   - extents를 0.3으로 축소: PolygonalMap2.VehiclePoly.init의 이동 차단
	     폴리곤은 extents 기반 2D 지면 폴리곤이라 비행 고도를 무시한다.
	     실제 크기를 넣으면 하늘에 떠 있어도 바닥에 투명 벽이 생긴다.
	     렌더/그림자는 model scale과 shadowExtents가 담당하므로 무관.
	   - part Engine 없음(의도적): addToWorld -> trySpawnKey가
	     getPartById("Engine") 존재를 게이트로 쓰므로, 파트를 빼면 스폰 시
	     주변에 차키가 생성되는 경로가 원천 차단된다.
	   - 엔진 사운드: 시동을 걸지 않으므로 미정의 이름을 넣어 무음 보장.
	   ═══════════════════════════════════════════════════════════════════ */
